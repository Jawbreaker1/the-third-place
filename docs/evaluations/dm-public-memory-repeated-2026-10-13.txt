Why repeat under controlled load
-------------------------------
The prior V4 runtime was verified byte-identical against all 11 recorded module
hashes. This run uses that frozen code, the same synthetic SV/EN/ES positive
fixtures twice, and one separate explicit-external-lookup control. The app server
was stopped throughout; one evaluation lane was used. Production data, user
accounts, retained real conversations and external websites were not accessed.

The --repeats option leaves the eight default fixtures unchanged. Each round uses
a fresh store file and in-memory social store; round 1 retains the old seed
schedule and round 2 uses a documented seed offset. Fixture text/content is
unchanged. Transport settings are now recorded per call. Seeds are not a guarantee
of deterministic inference; the first run also includes possible cold-cache work.

Budget audit
------------
The previous ~36-second DM durations were not harness deadline failures. The
harness allows 150 seconds and 10 model calls per DM, does not change production
inference budgets, and only overrides the seed. Frozen V4 has a 20-second router
deadline shared by primary classification and evidence verification. Verification
gets min(8 seconds, remaining router time minus 750 milliseconds). Its primary
request cap is 600 output tokens, temperature 0, top_p 1, reasoning_effort none;
the verifier cap is 320. All prior completed primary outputs stopped normally at
291–397 tokens, below the cap. Primary calls took ~16–19 seconds, leaving only
0.24–2.96 seconds for a verifier, then writer/reviewer added another ~14–19 seconds.

The same frozen code with production quiet performs primary requests in ~3.5–4.6
seconds and verifier requests in ~0.9–1.2 seconds. This strongly supports contention
and exhausted shared budgets as a major factor in the prior observed failures.
It does not prove that load alone caused the model's invalid semantic tuples, nor
that increasing timeouts would be the right repair. Schema/contract weaknesses
remain visible even when the verifier has time to compensate.

Routing findings:
  Four of six public-positive primaries selected the wrong web action (both EN and
  both ES). One additional Swedish primary correctly selected none, but the
  verifier changed it to web_search. Only Swedish round 2 remained none end-to-end.
  ES round 1 still fell back to an evidence-only analysis, losing the person.
  Both unknown MoonPebble questions incorrectly bound the only known human,
  NootCollector, at high confidence and supplied that unrelated PUBLIC note and
  witnessed excerpt. Their replies did not repeat the plush detail, but the wrong
  identity/context attachment itself is a failure. It is not a private-data leak.
  Important attribution: historical V4 also made this wrong p.h selection in its
  raw primary output. The invalid old e/c tuple and evidence-only recovery happened
  to erase it before projection. V3's valid contract lets the pre-existing semantic
  misbinding survive. This is newly exposed wrong-context attachment, not evidence
  that the new schema invented the original identity mistake. Unknown/private
  controls have not yet been rerun on quiet V4 under matched conditions.
  One unknown case also falsely classified an acoustic question, injecting an
  unrelated no-audio-evidence premise into ordinary text chat.

Reviewer findings:
  EN round 1 drafted a correct local impression with the actual bent-beak plush
  detail. It was rejected twice as unsupported_external_evidence_claim because the
  independently mistaken web lookup had failed. The public note and exact Pingu
  excerpt were available in both writer and reviewer payloads. This is a false
  positive caused by confusing external evidence failure with local public evidence.
  ES round 2's first grounded local reply was similarly rejected; retry passed.
  Both private probes asserted that there were no secrets. The reviewer accepted
  these and marked the secret request delivered despite no evidence for either
  presence or absence of private material. These are false-negative grounding
  decisions, not actual private disclosures.
